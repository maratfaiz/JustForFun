# Луми — маскот приложения: полное описание ассетов

Этот документ — всё, что нужно знать про персонажа и картинки к нему.
Он рассчитан на того, кто будет верстать приложение (человека или модель):
что это за файлы, куда какой ставить, как их показывать и как получить новые.

---

## 1. Кто такой Луми

Луми — жёлтая пятиконечная звёздочка с лицом, ручками и ножками. Маскот
приложения по самооценке: он не учитель и не тренер, а спутник, который
рядом. Отсюда характер:

* **тёплый, но не приторный** — мягкая улыбка, румянец, спокойные глаза;
* **поддерживающий, а не оценивающий** — он радуется вместе с пользователем,
  грустит вместе с ним и никогда не осуждает;
* **спокойный** — даже в радостных сценах нет крика и суеты.

Это влияет на то, как его показывать: Луми уместен в момент, когда человеку
нужно тепло (начало дня, завершение практики, тяжёлая тема), и неуместен как
украшение каждого экрана подряд.

## 2. Технические характеристики файлов

| Параметр | Значение |
|---|---|
| Формат | PNG, RGBA (с альфа-каналом) |
| Размер | 1024 × 1024 px, квадрат |
| Фон | полностью прозрачный |
| Тень под ногами | **не** запечена в файл |
| Цветовое пространство | sRGB |
| Вес файла | ~60–160 КБ |

Персонаж нарисован в общей координатной сетке, поэтому **во всех файлах он
одного масштаба и стоит на одном месте**. Это сделано специально: если
переключать картинки на одном экране (например, реакция на ответ), Луми не
будет прыгать и менять размер.

Границы непрозрачной области отличаются от сцены к сцене, потому что у сцен
разный реквизит:

* `mascot-ex1` (держит блокнот) — содержимое занимает примерно центральные
  50% кадра;
* `mascot-welcome` (стоит на планете) — планета уходит за нижний край;
* `mascot-sleeping` (кровать) — шире и выше обычного.

**Не обрезайте файлы по содержимому** и не центрируйте их автоматически по
bounding box — иначе персонаж поедет относительно других сцен. Ставьте PNG
целиком в квадратный контейнер.

### Иконка приложения

`assets/appicon-<вариант>.png`, три варианта фона: `night`, `violet`,
`cream`. Отличаются от всех остальных ассетов техническими требованиями
App Store:

* **1024 × 1024, RGB без альфа-канала** — иконка с прозрачностью не
  проходит проверку при загрузке;
* **без скруглённых углов** — маску накладывает система, свои скругления
  дадут двойной контур;
* фигура занимает 70% кадра и отодвинута от углов, потому что углы
  срезаются.

В Xcode кладётся в `Assets.xcassets` → `AppIcon`, в единственный слот
1024pt: остальные размеры система сгенерирует сама.

## 5. Как показывать в интерфейсе

* **Размер на экране.** Крупные сцены (заставка, приветствие, завершение
  практики) — 240–360 pt по стороне. Картинки в диалогах упражнений —
  120–180 pt. Иконки (`home-wardrobe`, `crisis`) — 56–96 pt.
* **Не растягивайте** — только пропорциональное масштабирование, файл
  квадратный.
* **Не перекрашивайте** и не накладывайте цветные фильтры: жёлтый Луми —
  часть узнаваемости.
* **Не добавляйте свечение и обводку.** Персонаж специально сделан без
  ореола: попытки «подсветить» его делают картинку грязной.
* **Тень.** Если нужна тень под персонажем — рисуйте её средствами UI
  (мягкий эллипс под нижним краем), в файлах её нет.
* **Анимация.** Файлы статичные. Для оживления достаточно лёгкого
  покачивания всего PNG (±2–3° поворота или ±4 px по вертикали, 2–3 секунды
  на цикл) — этого хватает, чтобы персонаж выглядел живым.
* **Смена сцен.** Так как масштаб и положение общие, переход между двумя
  сценами можно делать простым кросс-фейдом — персонаж не «дёрнется».

## 6. Откуда берутся файлы

Картинки не нарисованы в редакторе — они **генерируются кодом** на Python
(единственная зависимость — `pillow`). Значит, любую сцену можно
пересобрать в другом размере или поправить, не открывая графический
редактор.

```bash
pip install pillow

# все ассеты заново, 1024 px
python3 scenes.py --export assets --size 1024

# то же в другом размере
python3 scenes.py --export assets --size 512

# одна отдельная сцена
python3 -c "import scenes; scenes.render_scene('meditation', 1024).save('out.png')"
```

Файлы проекта:

| Файл | Что делает |
|---|---|
| `cute_star.py` | сам персонаж: форма звезды, руки-ноги, лицо, эмоции |
| `scenes.py` | сцены приложения: декор, реквизит, список `SCENES`, экспорт |
| `shop.py` | товары магазина в виде мини-сцен с маскотом |
| `items.py` | предметы магазина `item-*`: вещь без маскота, с объёмом |
| `appicon.py` | иконка приложения: Луми на фоне, RGB без альфы |
| `make_emotions.py` | лист эмоций `emotions.png` + отдельные PNG эмоций |
| `make_anatomy.py` | схема `anatomy.png` с подписями параметров |
| `MASCOT.md` | техническая карта: где какой параметр персонажа лежит |
| `scenes.png` | контактный лист всех сцен |

### Как добавить новую сцену

Одна запись в словаре `SCENES` внутри `scenes.py`:

```python
"newscreen": dict(
    pose="hold",                       # поза рук и ног
    face=F(eyes="closed", mouth="wide"),
    props=("hearts",),                 # реквизит вокруг
    back=[planet],                     # слои ЗА персонажем
    front=[big_heart, hands_notepad],  # слои ПЕРЕД персонажем
    title="Название для листа сцен",
),
```

Доступные значения:

* **позы:** `idle`, `wave`, `cheer`, `hold`, `point`, `clap`, `hug`, `sit`,
  `sit_hold`, `lotus`, `float`;
* **глаза:** `open`, `wide`, `closed`, `sleepy`, `wink`, `sparkle`, `up`;
* **брови:** `normal`, `raised`, `sad`, `angry`, `none`;
* **рот:** `smile`, `wide`, `open`, `small`, `sad`, `think`;
* **реквизит:** `sparkles`, `hearts`, `zzz`, `tear`, `question`;
* **декор сцен:** `planet`, `planets_small`, `cloud`, `bed`, `blanket`,
  `mat`, `headphones`, `music_notes`, `nightcap`, `beanie`, `press_hat`,
  `pillow`, `notepad`, `card`, `letter`, `big_heart`, `flag`, `rocket`,
  `hearts_around`, `think_bubble`, `big_question`.

## 7. Два правила, которые легко нарушить

1. **Предмет в руках рисуется между телом и руками.** Сначала предмет
   (`big_heart`, `notepad`, `card`, `letter`), сразу за ним — `hands_notepad`
   или `hands_heart`, которые кладут руки поверх. Если этого не сделать,
   предмет будет выглядеть приклеенным к животу.
2. **Мягкие пятна (тени, румянец) строятся через маску.** Размывать
   RGBA-слой напрямую нельзя: у прозрачных пикселей чёрный RGB, и размытие
   подмешивает грязь в цвет. В коде для этого есть `soft_layer()`.

Подробности — в `MASCOT.md`.
